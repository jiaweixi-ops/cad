# V0.1 Acceptance

## Automated/local checks

Run from the repository root:

```powershell
.\tools\verify-v01.ps1
```

The script checks the project skeleton, command names, AutoCAD reference copy policy, Core isolation, forbidden V0.1 behaviors, and existing build output for copied Autodesk Managed DLLs. Missing required files must be reported as validation failures rather than terminating the verifier unexpectedly.

This script is not a substitute for a real AutoCAD host test.

## Build gate

The AutoCAD 2025 project does not assume a machine-specific installation directory. Set either:

```powershell
$env:AUTOCAD_MANAGED_API_DIR = '<your AutoCAD 2025 Managed API directory>'
```

or pass the MSBuild property `AutoCADManagedApiDir` explicitly.

The directory must contain the real matching AutoCAD 2025 assemblies:

- `AcMgd.dll`
- `AcDbMgd.dll`
- `AcCoreMgd.dll`

The build intentionally fails with a clear error when those assemblies cannot be resolved. The build must produce `CADProjectManager.AutoCAD.dll` without copying Autodesk Managed DLLs into the plugin output.

## Gate A: plain AutoCAD baseline

Before loading CADProjectManager, AutoCAD 2025 itself must start normally and reach a usable drawing workspace.

If plain AutoCAD fails before `NETLOAD`, stop the plugin acceptance run. Record the host failure separately and keep V0.1 as `source-ready / host-unverified`; a pre-NETLOAD host failure is not evidence of a CADProjectManager defect.

## Manual AutoCAD gate

Only after Gate A passes:

1. Close unrelated AutoCAD documents or use a disposable test drawing.
2. Load the built adapter with `NETLOAD`.
3. Run `CADPM_HEALTH` 100 consecutive times and confirm no command exception.
4. Run `CADPM_INFO` and confirm plugin/config/log status is reported accurately.
5. Compare the drawing and relevant system variables before/after; no DWG data or system variable may change because of the plugin.
6. Open/close 20 test drawings, create/save/Save As, Undo/Redo, Plot Preview, switch documents, and exit AutoCAD.
7. Confirm logging stays in the plugin private data root and a simulated log failure does not terminate AutoCAD.
8. Close AutoCAD normally and verify there is no shutdown hang or plugin-caused error.

Until these checks are executed in the actual AutoCAD host, V0.1 remains `source-ready / host-unverified`, not `PASS`.

## Core Console smoke test

The repository includes a staging script that expects the built plugin at this ASCII-only path:

```text
D:\Temp\CADProjectManager.V0.1\CADProjectManager.AutoCAD.dll
```

Example setup from the repository root:

```powershell
$stage = 'D:\Temp\CADProjectManager.V0.1'
New-Item -ItemType Directory -Force $stage | Out-Null
Copy-Item '.\src\CADProjectManager.AutoCAD\bin\Debug\net8.0\*.dll' $stage

$core = '<AutoCAD 2025 install>\accoreconsole.exe'
$dwg = '<disposable or Autodesk sample DWG>'
& $core /i $dwg /s '.\tools\v01-accoreconsole-staged.scr'
```

The Core Console run is only a smoke test. A host failure before the script executes must be treated as a host/environment blocker, not as plugin acceptance evidence. The full GUI lifecycle matrix remains required before marking V0.1 `PASS`.
