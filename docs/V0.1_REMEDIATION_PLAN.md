# V0.1 验收整改方案

## 结论

当前 V0.1 源码与构建骨架基本合格，但尚不能标记为 `PASS`。

当前正式状态：

```text
source-ready / host-unverified
```

原因：真实 AutoCAD 2025 GUI 宿主中的 `NETLOAD`、100 次 `CADPM_HEALTH` 与完整生命周期测试尚未完成。

在完成本文件的宿主验收前：

- 不进入 V0.2 Palette 开发；
- 不加入 SQLite；
- 不加入压缩包导入；
- 不加入 DWG 扫描；
- 不加入 AI；
- 不加入后台线程或文件监听。

---

## 已完成整改

### 1. 完整异常边界

原问题：`GlobalExceptionBoundary.Execute()` 在进入 `try` 之前读取 `Application.DocumentManager.MdiActiveDocument` 和 `Editor`，理论上仍存在宿主 API 异常泄漏到 AutoCAD 的窗口。

整改：

- DocumentManager / MdiActiveDocument / Editor 获取全部纳入主 `try`；
- 错误日志再次使用独立 `try/catch`；
- 向 AutoCAD 命令行回报失败也使用独立 `try/catch`；
- 恢复/报告阶段的异常不得再次泄漏。

目标：

> CADProjectManager 命令失败时，只允许插件命令失效，不允许因为异常边界遗漏拖垮 AutoCAD。

---

### 2. 强化静态安全验收脚本

`tools/verify-v01.ps1` 已增强：

1. 分别检查：
   - `AcMgd`；
   - `AcDbMgd`；
   - `AcCoreMgd`。
2. 三个引用都必须明确：

```xml
<Private>false</Private>
```

3. 如果 `src/CADProjectManager.AutoCAD/bin` 已存在，扫描全部输出目录，禁止出现：

```text
AcMgd.dll
AcDbMgd.dll
AcCoreMgd.dll
```

4. 继续检查 V0.1 禁止行为：
   - 网络访问；
   - HttpClient；
   - FileSystemWatcher；
   - Timer；
   - SendKeys；
   - Process.Kill；
   - Environment.Exit；
   - Application.Quit。
5. Core 项目继续禁止引用 AutoCAD API。

注意：

> 静态脚本通过不等于真实 AutoCAD 宿主验收通过。

---

### 3. 修正 AutoCAD 2025 构建说明

当前 adapter：

```text
AutoCAD 2025
.NET 8
TargetFramework = net8.0
```

因此当前 V0.1 构建前提应为：

- Visual Studio 2022 / MSBuild，或 .NET 8 SDK；
- AutoCAD 2025 Managed API；
- `AcMgd.dll`；
- `AcDbMgd.dll`；
- `AcCoreMgd.dll`。

`.NET Framework 4.8 Developer Pack` 不再列为 AutoCAD 2025 adapter 的必要前提。

未来支持 AutoCAD 2021–2024 时再单独建立 .NET Framework 适配工程。

---

### 4. 整理进度状态

`progress.md` 已拆分成：

```text
Build / Static Verification
            ↓
已完成

            ↓
未完成
```

避免后续开发者误把“成功 build”理解成“插件已经在 AutoCAD 中验收通过”。

# 下一步：真实 AutoCAD 2025 GUI 验收

## Gate A：启动基线

1. 正常启动 AutoCAD 2025。
2. 使用一次性测试 DWG。
3. 在插件加载前记录关键系统变量。
4. 确认 AutoCAD 本身可以：
   - 新建；
   - 打开；
   - 保存；
   - 关闭 DWG；
   - Undo/Redo；
   - Plot Preview；
   - 正常退出。

如果纯 AutoCAD 本身已经异常，先停止插件验收。

---

## Gate B：NETLOAD

在 AutoCAD 2025 GUI 中执行：

```text
NETLOAD
```

加载：

```text
src\CADProjectManager.AutoCAD\bin\Debug\net8.0\CADProjectManager.AutoCAD.dll
```

预期：

- DLL 成功加载；
- 无异常弹窗；
- 无崩溃；
- 无明显卡顿；
- 不自动创建 UI；
- 不自动打开图纸；
- 不联网；
- 不启动后台扫描。

失败则立即记录：

- AutoCAD 命令行输出；
- 异常文本；
- 日志；
- AutoCAD 版本；
- 插件 build SHA。

不得继续后续 Gate。

---

## Gate C：CADPM_HEALTH

执行：

```text
CADPM_HEALTH
```

预期类似：

```text
CAD Project Manager
Status: OK
Version: 0.1.0
AutoCAD: ...
Runtime: ...
Mode: SAFE MODE
```

然后连续执行 100 次。

验收条件：

```text
100 / 100 成功
0 command exception
0 AutoCAD crash
0 AutoCAD freeze
```

---

## Gate D：CADPM_INFO

执行：

```text
CADPM_INFO
```

检查：

- Plugin path 正确；
- Config path 指向 `%LOCALAPPDATA%\CADProjectManager\config`；
- Log path 指向 `%LOCALAPPDATA%\CADProjectManager\logs`；
- 不指向 AutoCAD 安装目录；
- 不指向用户 DWG 目录。

---

## Gate E：生命周期测试

在插件已加载的情况下执行：

1. 新建 DWG；
2. 打开 DWG；
3. 关闭 DWG；
4. 保存；
5. 另存为；
6. Undo；
7. Redo；
8. Zoom；
9. Pan；
10. Plot Preview；
11. 同时打开多个 DWG；
12. 多文档切换；
13. 重复关闭/重新打开测试图。

至少打开/关闭 20 个测试 DWG。

预期：

```text
AutoCAD 行为与未加载插件时一致
```

---

## Gate F：系统变量零影响

加载前后比较至少：

```text
SECURELOAD
TRUSTEDPATHS
APPAUTOLOAD
CMDECHO
FILEDIA
OSMODE
ORTHOMODE
PICKFIRST
PICKADD
LTSCALE
PSLTSCALE
INSUNITS
```

必须：

```text
Before == After
```

插件不得为了方便修改：

```text
SECURELOAD = 0
```

---

## Gate G：DWG 零修改

准备：

```text
test_original.dwg
```

加载插件、执行 V0.1 命令后保存一个测试副本。

比较：

- Entity 数量；
- Layers；
- Blocks；
- Layouts；
- Xrefs；
- DimStyles；
- TextStyles；
- Dictionary；
- Audit 结果。

V0.1 只读阶段不得产生插件引起的业务数据变化。

---

## Gate H：退出 AutoCAD

正常关闭 AutoCAD。

验收：

- 不阻塞退出；
- 不出现插件异常；
- 不要求等待网络；
- 不保存用户 DWG；
- 日志失败也不得影响退出。

# Core Console 当前问题

此前 AutoCAD Core Console 在插件脚本执行前出现：

```text
Unhandled Delayload "AcGeomentObj.dbx" Module Not Found
```

当前处理原则：

- 保留诊断证据；
- 不把它归因于 CADProjectManager；
- 不再让该问题阻塞 V0.1 的首轮 GUI 验收；
- 先使用正常 AutoCAD 2025 GUI 完成 `NETLOAD` 主验收；
- Core Console 环境问题后续单独排查。
